# Spec 0002: public tamper corpus and a score

Status: implemented on branch `tamper-corpus`.

## Problem

"Gauntlet catches tampering" is a claim. A sceptical reviewer wants the cases
it was tested against, how many it catches, and how often it fires when nothing
was weakened. Today the only evidence is `gauntlet selftest`, which generates
its fixtures on the fly from a project's files and reports caught or not, with
no negatives and no rate.

## What it is

A committed corpus under `corpus/tamper/`, one case per directory:

```text
corpus/tamper/<pack>/<case>/
  tamper.patch    a unified diff against the pack's fixture in examples/fixtures
  expected.json   {"kind": "positive", "finding": "<integrity check>"} or {"kind": "negative"}
  NOTE.md         what the case does and why it should (or shouldn't) be caught
```

**Positives** are the built-in selftest tampers, written out as concrete patches
against each pack's real fixture: a deleted test, an added skip, a weakened
assertion, an added suppression, and test code referenced from main code.
They're generated by `gauntlet corpus --export` from the packs' own tamper
generators, then committed, so the corpus is stable and reviewable.

**Negatives** must not fire. Each pack has three, hand-written:

- a **renamed test**, with its body unchanged;
- an **extracted helper**, moving setup out of a test into a function it calls;
- a **tightened assertion**, replacing a loose check with a stricter equivalent.

## The command

`gauntlet corpus` runs every case. For each pack it copies the fixture into a
temporary repository, commits it as the base, applies each case's patch on a
branch, and runs a check that skips the gates (the same mode `selftest` uses for
fixtures caught without execution): diff facts, policy and the integrity
detectors only. That keeps the corpus fast and deterministic.

- A **positive** is detected when the expected integrity finding is reported.
- A **negative** is a false positive when any integrity forbid fires.

It prints, per pack and in total, the measured **detection rate** (positives
detected / positives) and **false-positive rate** (negatives that fired /
negatives), then each case that didn't meet its expectation. `--json` prints
the same as JSON. The numbers are whatever the run measures: nothing in the
README or the output states a rate that wasn't measured by this command.

The exit code is 1 when any case misses its expectation, so CI shows a missed
detection or a false positive as a failure.

## Wiring

- The corpus runs as an ordinary test (`packages/cli/test/corpus.test.ts`): it
  needs only git and the built-in parsers, no language toolchains. CI's `test`
  job runs it on every pull request, so any change to `.gauntlet/`, a pack or
  the corpus runs it, with no workflow change. The test pins the measured
  results: a lost detection or a new false positive fails it.
- `corpus/` is test data that defines the score. Protecting it needs a policy
  edit (`fixtures "corpus/**"` in `.gauntlet/policy.gx`), a **protected file**,
  so it ships as `docs/specs/patches/0002-protect-corpus.patch` for the owner to
  apply.

## Measured results

56 cases, 8 per pack. Every positive is detected: 35/35. Seven of 21 negatives
fire, one per pack, all the **renamed test**: renaming a test with its body
unchanged reads as `deleted-tests`. The extracted-helper and
tightened-assertion negatives fire nowhere. Teaching the detectors renames is a
detector change, out of scope here. The full corpus runs in about 16 seconds.

## Tests

- Unit: reading cases (an unreadable case is reported, not skipped), scoring,
  the rates and the table.
- The committed corpus against the real fixtures, as an ordinary test: every
  pack has its positives and the three negatives, every positive is detected,
  and the false positives are exactly the known renamed-test cases.
