# 0027. Bun's tests are named after their files, and older baselines still match

Status: accepted. Changes the ids of tests run by `bun test`.

## Context
Integrity names each test by an id from the runner's JUnit XML, `<classname>.<name>`: the deleted-tests check compares the base's ids with the head's, and test selection (spec 0013) excuses the tests of a test file it left out by the file at the start of their ids. Vitest's classname is the test's file, so its ids are `test/money.test.ts.money > adds`. Bun's classname is only the describe path, innermost first (`inner > grp`), and empty at the top level, so its ids were `inner > grp.adds` or `.adds`. Two files' tests with the same describe path and name had one id, so deleting one of them wasn't caught, and selection couldn't tell which file a bun test was in. Bun's JUnit has a `file` attribute on each test case, with the path from the directory `bun test` ran in: the repository's root, or a build's folder.

## Decision
- **The id.** A test case in a report whose root is `<testsuites name="bun test">` and that has a `file` is `<file>.<classname>.<name>`, or `<file>.<name>` when the classname is empty: `test/money.test.ts.inner > grp.adds`, `test/money.test.ts.adds`. The file uses `/` and has no leading `./`. What follows the file is exactly the old id (less its leading `.`), rather than Vitest's `describe > name` order: describe names can hold `>` and `.`, so only this keeps the old id recoverable. It is still `<file>.<rest>`, the shape selection, a failure's file lookup and the removed-with-its-code check read. Other runners' ids don't change, even with a `file` attribute.
- **Older baselines.** A base id the head's run doesn't have is matched to a head id that is that id with a script file's name in front (`<file>.` + the old id; a build's `<folder>:` stays in front). The base id then takes the head's name. When several head ids match (the same describe path and name in two files, one id before), it takes the first: it still ran, and the migration never makes a test look deleted. A base id no head id carries is left as it is, so a test that really went is still reported as no longer running. Ids are replaced one for one, so the executed-tests count doesn't change. This applies wherever the baseline's ids meet a run's: integrity's deleted-tests check and ratchet (`testsToCompare`), a change that only removes tests (`removedTests`, spec 0016), and whether the CI's reports hold every test the base ran (ADR 0024).
- No version check: the old shape is recognised from the ids themselves, so the migration does nothing on a baseline recorded with the new ids.

## Consequences
- Deleting one of two same-named bun tests in different files is caught, once the baseline names them the new way. Until then, removing one of a pair that shared an old id isn't: the old baseline can't say there were two.
- Upgrading Gauntlet doesn't block the next change. Gauntlet's own repository is a case: a pull request is judged by Gauntlet built from its base, so the change that brings this is judged with the old ids, and every later one compares new ids with the committed baseline's old ones through the migration.
- Recording the baseline again (`gauntlet baseline`) stores the new ids, and the migration then matches nothing. It can be removed once supported baselines are all recorded with the new ids; removing it makes an older baseline report every bun test as no longer running.
- A quarantine (ADR 0017) names a test by its id. One that names a bun test the old way no longer matches it, so a quarantined failure fails the suite until the policy names the test the new way (the report gives the id). That fails safe: a quarantine is an owner's dated exception, and a policy names it again rather than Gauntlet guessing which file's test it meant.
- Selection for bun (spec 0013) can excuse a left-out test by its file once its map is recorded, and a map is recorded only with a baseline, which then has the new ids.
- Bun's kill maps aren't affected: Stryker's command runner for bun reports no killers, so no kill map names bun tests.
